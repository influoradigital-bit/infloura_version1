## What was observed

The four literal DONE_WHEN clauses all hold: on the real repo it exits 1 with 15 findings (including the canonical F-0416 record POST /wallet/escrow/refund at EscrowController.java:117), on a clean harness it exits 0, and it exits 2 in four distinct can't-run modes (missing controller tree, 0 controller files, 0 endpoints parsed, missing FE clients) — there is NO vacuous pass, and running it creates and modifies nothing (git status unchanged at 254 entries; the one pyc predates the run and is gitignored). Precision is also real: I checked all 15 reported paths against src/, e2e/ and the root lib/hooks — zero literals, zero dynamic call sites — and read the two most plausible "legitimate server-side route" candidates (/notifications/unsubscribe, /workspace/members/accept), both of which take @AuthenticationPrincipal plus a JSON body and so are genuine UI routes; 15/15 true positives, 0 false positives. I nonetheless refute it, because it catches the SHAPE of the examples rather than the defect class. In an isolated harness (clean=0, canonical dead route=1, both verified) the identical dead money route slipped past with exit 0 in seven different restatements: written as method-level @RequestMapping(value=..., method=RequestMethod.POST) (METHOD_MAPPING only knows @Get/Post/Put/Patch/DeleteMapping); placed in a subpackage web/wallet/ (collect_backend uses a non-recursive os.listdir — two real controllers already live outside that directory today); placed in a file named EscrowResource.java (filename must end "Controller.java"); written as @PostMapping(path={"/refund"}), where the unparsed array collapses the endpoint to /wallet/escrow, a path the frontend really does call; greened by a plain string literal '/wallet/escrow/refund' sitting in a breadcrumb LABEL map (any "/..." string in any src file counts as a caller, not just a request argument); greened by an unrelated file declaring const API_BASE='/wallet/escrow' next to a '/refund' string; and parked under /internal/ where the prefix-only allowlist swallows it. The inverse hole exists too — a live route called as '/api/v1/wallet/'+RESOURCE+'/'+ACTION reports as dead (exit 1) — though nothing in the repo triggers it today. I verified none of the annotation-shape evasions currently exist in the tree, so the present 15 findings are sound; the gate is one ordinary Spring idiom or one stray UI string away from silently greening the very defect it was written for, which is why it should not be recorded as proven for the class.

## Required fix (the minimum change that would make this gate real)

(1) Discover controllers by content, not location or filename: recursively walk influora-api/src/main/java for classes annotated @RestController/@Controller instead of os.listdir on web/ filtered to *Controller.java. (2) Parse the remaining mapping shapes — method-level @RequestMapping(method=...), array-valued value/path ({"a","b"}), and multi-value class mappings. (3) Fail loud instead of guessing: when a mapping's path argument does not resolve to a string literal (constant reference, array, concatenation), exit 2 naming the file/line rather than emitting a mangled path that can silently match a live route. (4) Harvest frontend paths only from actual request call sites — the argument position of fetch/apiRequest/http.request/axios/api.* — not from every "/..." string literal in every src file, and drop the blanket API_BASE prefixing of unrelated literals. (5) Justify allowlist entries by controller evidence (no @AuthenticationPrincipal, signature-verified webhook, redirect response) rather than by path prefix, so a route cannot be exempted by naming it /internal/.
