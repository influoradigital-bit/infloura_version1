## What was observed

It leaves no litter (git status: 246 entries before and after; no new __pycache__ entry, since it runs as __main__). That is where the good news stops. (1) GREEN ON BAD INPUT, decisive: I copied the real defective creator-discovery.tsx to a temp dir (control run: FAIL, 4 findings, exit 1), then applied a pure identifier rename on 16 lines — setVerifiedOnly->applyVerifiedOnly, setSortBy->applySortBy, setEngagementRange->applyEngagementRange, setSelectedLanguages->applySelectedLanguages. (2) I then built a minimal 26-line fixture the gate DOES catch (paginated api.creators.search + verifiedOnly consumed only in a useMemo filter + bound to onChange -> exit 1) and mutated it seven ways, each preserving the identical defect. (3) SCAN ROOT BLIND SPOT: the default SCAN_ROOT is REPO/src/components only — 213 files. src/pages (72 candidate files) and src/admin (25) are never scanned by the default invocation. F-0412, one of the gate's own three claimed records, lives in src/pages/creator-campaigns.tsx (searchQuery filtered client-side at line ~132 against a browse() call carrying page/limit at 87-88) and is invisible to the default run; it only appears when I manually pass src/pages. (4) FALSE POSITIVES: rule B (RE_NOOP_HANDLER) is a bare regex disconnected from the four-part evidence chain the header describes — no pagination requirement, no state requirement. Pointed at src/pages it produced 3 findings, 2 of which are false: src/pages/creator-settings.tsx:636 and :649 flag `<TaxIdentityForm onSubmitted={() => {}} />` and `<KycIdentityForm onSubmitted={() => {}} />` as "control is wired to an empty function". Those are not controls; `onSubmitted?: () => void` is an OPTIONAL completion-notification callback prop on a child component (TaxIdentityForm.tsx:64,67,76,80 — it calls `await submit({...})` then `onSubmitted?.()`). The forms submit to the server correctly; the parent simply has nothing to do afterward. Passing a no-op for an optional callback is idiomatic React and rule B will flag every instance of it in the codebase. Tally: 5 findings verified genuine (4 default + creator-campaigns searchQuery), 2 verified false. Bottom line — the gate is a working detector for the exact lexical shape of F-0405 and nothing else. It cannot survive a rename, a function declaration, a different HTTP client name, or a file one directory over, and its "demonstrated to fail on bad input" claim holds only for input that already looks like the example it was written from.

## Required fix (the minimum change that would make this gate real)

Five changes, in order of severity. (1) Stop keying state discovery on the "set" prefix: take the useState tuple's second element as the setter regardless of its name (RE_STATE line 62), so a rename cannot silence the gate. Add a self-falsification step to the gate itself — run against an in-tree fixture whose setters are renamed and assert it still exits 1. (2) Widen SCAN_ROOT from REPO/src/components to REPO/src (excluding node_modules/__tests__/*.test.tsx as now) and extend the extension filter to .tsx and .jsx; otherwise the gate cannot see F-0412, its own record. (3) Replace the three-name client whitelist in RE_API_CALL and the six-word PAGINATION_KEYS tuple with structural detection: treat any awaited call whose object-literal argument contains a numeric-looking key from a broader set (page|pageNumber|offset|skip|start|cursor|limit|take|size|pageSize|perPage|first) as a paginated server call, and detect any `await <ident>.<ident>(...)` inside a function that also sets state, not just api/apiClient/meeraApi. (4) Broaden control binding and client-side consumption: match `function name(...)` declarations as setter aliases alongside const-arrows (RE_LOCAL_FN line 70), and treat any read of a control-bound state variable anywhere in the derivation of the rendered list — including plain `if (x) rows = rows.filter(...)` outside useMemo, and .reduce/.flatMap/.some — as client-side consumption, rather than only useMemo bodies and .filter/.sort/.slice arguments. (5) Fix rule B's false positives: require the on[A-Z] no-op to be on a lowercase (host/DOM) JSX element, or on a known interactive primitive (Button/Checkbox/Switch/Select/Slider), and exclude props whose declared type on the child is optional — a `() => {}` passed for an optional callback prop such as `onSubmitted?: () => void` is not a dead control and must not be reported.
