1 · Ship-blocking errors

These prevent a correct production build or expose the app. Address before any deploy.

Production build fails — Chrome path is hardcoded F-0055 High

scripts/prerender.mjs:107
Symptomnpm run build exits 1. The postbuild prerender step resolves Chrome from 8 hardcoded absolute paths, and PRERENDER_CHROME_PATH is set in no .env, package.json script, or CI workflow. dist/ contains only index.html + assets — 0 of 16 prerendered route directories, so the marketing/SEO shells are never produced.
Why it slippedgates/build.sh would catch this, but no pipeline step invoked it; the earlier audit pass even ran the command with an undeclared PRERENDER_CHROME_PATH override and recorded it green (see F-0059).
Fix → Make Chrome discovery env-driven: read PRERENDER_CHROME_PATH, fall back to puppeteer's bundled binary, and fail loudly with an actionable message. Wire gates/build.sh into CI so a broken build can never merge.

2 · Security & governance gap

Not a bug in the code — a hole in what is being checked. This is the single largest blind spot in the whole audit.

No secret scanning has ever run on this repo F-0057 High

.proof-os/gates/security.sh · .proof-os/gates/frontend.sh
Symptomgitleaks reports UNAVAILABLE in both gates, so no credential scan has ever executed. .env.local and .env.production sit at the repo root and git history has never been scanned. Live AWS keys, tokens, or private keys in this tree would not have been seen.
Why it slippedBoth gates correctly downgrade to exit 2 (unavailable) on a missing tool — but nothing tracks that the tool has been missing every single run, so "unavailable" quietly reads as "fine".
Fix → Install gitleaks (or trufflehog) locally and in CI; scan the working tree and full history; confirm .env* is gitignored and rotate anything that was ever committed.

3 · Product bugs (broken UX for real users)

These compile and type-check cleanly but do the wrong thing at runtime — mostly brand-side messaging/navigation.

Offer/invite redirect drops the record id F-0060 Medium

src/components/brand/discover/creator-discovery.tsx:536
SymptomAfter a brand sends an offer or invite from Discover Creators, navigate('/brand/chat') carries no ?deal= or ?creator=. BrandChatPage has nothing to select, so it opens liveDealRooms[0] — a different creator's thread — or nothing. Both submit paths (deals.create :507, creators.invite :522) already return a usable id (DealResponse.id, InviteResponse.collaborationId) that simply isn't passed.
Why it slippedA route string is just a string to tsc/eslint; nothing asserted a post-submit redirect identifies the record it just created.
Fix → Append ?deal=<id> (or ?creator=) to the redirect from both submit handlers. A vitest guard creator-discovery-redirect.test.tsx is the assertion.

Brand chat latches onto an arbitrary room F-0061 Medium

src/pages/brand-chat.tsx:921,927
SymptomsetSelectedDeal(match || liveDealRooms[0]) opens an arbitrary room whenever the URL param is absent or unmatched, and the effect's guard makes that pick permanent — no later loadDealRooms() refresh corrects it. brand-messages.tsx already has the correct shape (return without selecting when a supplied param is unmatched); brand-chat.tsx never got that fix.
Why it slippedThe "audit #10" fix was applied to brand-messages.tsx only. Nothing checks that a fix to one of two parallel message surfaces reaches the other (RETENTION rule 4 — closure closes detection, not the remaining sites).
Fix → Port the brand-messages.tsx:396-405 guard: if a param was supplied but unmatched, return without auto-selecting.

"Message" button lands on an empty thread — id-space mismatch F-0062 Medium

src/pages/brand-creator-profile.tsx:571
SymptomThe Message button navigates to /brand/messages?creator=<CreatorProfile id>, but brand-messages.tsx:274 keys its thread list on deal.counterpartyId, which the backend populates from collaboration.getCreatorId() — a User id. The lookup can never match, so the brand lands with no thread selected. The FE CreatorProfile already carries userId (src/lib/types.ts:508); it's just not used.
Why it slippedNo gate compares the id space a URL param is produced in against the id space its consumer indexes on; tsc sees two strings.
Fix → Pass creator=<profile.userId> instead of the profile id.

FE/BE contract guardrail has rotted F-0058 Medium

src/lib/__tests__/api-contract.test.ts:118
SymptomThe contract test passes only because 38 paths are on a deferred allowlist. 19 of them now HAVE backend controllers but are still exempted, so their FE/BE parity is no longer checked; the other 18 have no backend mapping at all.
Why it slippedThe guardrail asserts only that non-allowlisted paths resolve; nothing asserts that allowlisted paths are still absent, so the list silently rots into a blind spot.
Fix → Add a reverse assertion: fail if an allowlisted path now resolves (it should graduate off the list). Prune the 19 that are implemented.
