# Influora — Server-Side Database Guide

> Production/staging MySQL 8 running on the Hostinger VPS (`influora-test` Docker Compose project).
> Covers: how to connect, where the passwords live, how to inspect the DB, and copy-paste
> SELECT / INSERT / UPDATE templates for **every table** (78 tables).
>
> Schema source of truth: Flyway migrations in `influora-api/src/main/resources/db/migration/`
> (95 files). This document was generated by parsing those migrations, so the column lists
> below match what the app actually creates. When in doubt, always trust `SHOW CREATE TABLE`
> on the live database over any document.

## 1. Where the credentials live (check these files)

The database password is **not** hard-coded in source — it comes from environment files. There are
two separate environments; do not mix them up.

### A. Local development (your laptop) — `docker-compose.yml` + `influora-api/.env`
| Setting | Value |
|---|---|
| Defined in | `docker-compose.yml` (root) → `mysql:` service, and `influora-api/.env` (lines 47-49) |
| Host / Port | `localhost` : **3307** (mapped from container 3306) |
| Database | `influora_local` |
| User / Password | `root` / `root`  (also `influora` / `influora`) |

### B. Server / VPS (Hostinger VM 1844961) — `/docker/influora-test/` on the server
| Setting | Value |
|---|---|
| Defined in | `/docker/influora-test/docker-compose.yml` and its `.env` (same directory) |
| Container | `influora-test-mysql-1` |
| Database | **`influora`** |
| App user / password | `influora_app` / *(value in `MYSQL_PASSWORD` in the server `.env`)* |
| Root user / password | `root` / *(value in `MYSQL_ROOT_PASSWORD` in the server `.env`)* |
| Host port | **none** — 3306 is container-internal only (not published to the host) |

To read the real passwords on the server:
```bash
cat /docker/influora-test/.env | grep MYSQL
# MYSQL_ROOT_PASSWORD=...
# MYSQL_PASSWORD=...
```
The Spring Boot service reads the same value via `SPRING_DATASOURCE_PASSWORD: ${MYSQL_PASSWORD}`
in `/docker/influora-test/docker-compose.yml`.

> ⚠️ The server `.env` also holds live third-party secrets (Anthropic, Cloudflare R2, Meta,
> SMTP, MSG91). Do not paste that file into chats, screenshots, or tickets.

## 2. How to connect (server side)

Because MySQL's port is not published to the host, you connect by exec-ing into the container.
Run these on the VPS shell (`ssh root@200.141.1.6`).

**Open an interactive SQL shell:**
```bash
# as the application user
docker exec -it influora-test-mysql-1 mysql -uinfluora_app -p influora
# it will prompt for the password (paste the MYSQL_PASSWORD value)

# or as root (full privileges)
docker exec -it influora-test-mysql-1 mysql -uroot -p influora
```

**Run a single query without opening a shell:**
```bash
docker exec influora-test-mysql-1 mysql -uroot -p'THE_ROOT_PASSWORD' influora \
  -e "SHOW TABLES;"
```

**Pipe a whole .sql file into the database:**
```bash
docker exec -i influora-test-mysql-1 mysql -uroot -p'THE_ROOT_PASSWORD' influora < queries.sql
```

> Tip: putting the password directly after `-p` (no space) avoids the prompt but leaves it in
> your shell history. Prefer the bare `-p` prompt on shared machines.

SHOW DATABASES;                       -- list all databases

SHOW TABLES;                          -- list all tables in influora

**Which migrations have run (Flyway history):**
```sql
SELECT version, description, success, installed_on
FROM flyway_schema_history
ORDER BY installed_rank;
```

**Row counts for every table at once:**
```sql
SELECT table_name, table_rows
FROM information_schema.tables
WHERE table_schema = 'influora'
ORDER BY table_name;
```

**Database size:**
```sql
SELECT table_name,
       ROUND((data_length + index_length)/1024/1024, 2) AS size_mb
FROM information_schema.tables
WHERE table_schema = 'influora'
ORDER BY (data_length + index_length) DESC;
```

## 5. Conventions used by this schema

- **Primary keys** are `id VARCHAR(26)` (ULID strings) on almost every table — **not**
  auto-increment. You must supply the `id` yourself on INSERT (generate a ULID/UUID in the app,
  or use `UUID()` for ad-hoc rows).
- `created_at` / `updated_at` default to `CURRENT_TIMESTAMP` (and `updated_at` auto-updates), so
  the INSERT templates below **omit them** — let the DB fill them in.
- Columns typed `JSON` expect a JSON literal, e.g. `'["instagram","youtube"]'`.
- `ENUM` columns only accept their declared values — check `SHOW CREATE TABLE` for the allowed set.
- `?` are bind-parameter placeholders. Replace with literals (quote strings/dates) when running by
  hand: `'value'`, `123`, `'2026-07-24'`, `'2026-07-24 10:30:00'`.

## 7. Other useful queries

**Find a user and everything about them:**
```sql
SELECT id, email, user_type, status, created_at FROM users WHERE email = ?;
```

**Brand workspace + its campaigns:**
```sql
SELECT w.name, c.title, c.status, c.budget_min, c.budget_max
FROM workspaces w
JOIN campaigns c ON c.workspace_id = w.id
WHERE w.id = ?;
```

**Wallet balances:**
```sql
SELECT owner_id, owner_type, balance, escrow_balance, currency
FROM wallets
WHERE owner_id = ? AND owner_type = ?;
```

**Recent AI (Meera) conversations:**
```sql
SELECT c.id, c.title, m.role, m.content, m.created_at
FROM ai_conversations c
JOIN ai_messages m ON m.conversation_id = c.id
ORDER BY m.created_at DESC
LIMIT 50;
```

## 8. Backup & restore (server side)

**Dump the whole database to a file on the VPS:**
```bash
docker exec influora-test-mysql-1 mysqldump -uroot -p'THE_ROOT_PASSWORD' \
  --single-transaction --routines --triggers influora > /root/influora_backup_$(date +%F).sql
```

**Dump a single table:**
```bash
docker exec influora-test-mysql-1 mysqldump -uroot -p'THE_ROOT_PASSWORD' \
  influora campaigns > /root/campaigns.sql
```

**Restore a dump:**
```bash
docker exec -i influora-test-mysql-1 mysql -uroot -p'THE_ROOT_PASSWORD' influora < /root/influora_backup.sql
```

## 9. Safety notes

- The `influora-test` stack runs with `APP_ENV=dev` / `SPRING_PROFILES_ACTIVE=dev` — it is the
  staging/test environment, safe to inspect and edit. Confirm this is the DB you intend before
  running any write/DELETE.
- Never run `DELETE`/`UPDATE` without a `WHERE`, and prefer wrapping writes in
  `START TRANSACTION; ... ROLLBACK/COMMIT;`.
- Flyway owns the schema. Do **not** hand-edit table structure (ADD/DROP COLUMN) on the server —
  add a new `V…__*.sql` migration in the repo and redeploy, or Flyway's checksum validation will
  fail on next boot.
- Table `shedlock` is used by the scheduler for distributed locks; `flyway_schema_history` is
  Flyway's own bookkeeping. Leave both alone.
