Important points & gaps (fix first)

  • C19 Submit deliverable — the single break in the money journey. Backend (POST /creator/deliverables/:id/submit) is deployed and live (403), but the creator's submit form in creator-chat.tsx is a setTimeout(1500) simulation and never calls api.deliverables.submit. A creator literally cannot deliver work end-to-end.
  • C14 Counter-offer — same pattern: POST /deals/:id/counter exists and is live, but the chat counter form is a stub. Accept/reject work; negotiation-by-counter does not.
  • C3 / login — the "Forgot password?" control on /creator/login is a dead button (type=button, no handler). The reset flow works only if you hit the URL directly.
  • C32 settings — notification toggles beyond "Email" are local-state only; the Tax Identity form is wired to a deliberate NOT_IMPLEMENTED (no GST endpoint yet).
  • Dashboard expectation gap — the "store / coupons quick-access" mental model isn't met: the creator dashboard surfaces Affiliate + Public page, but Coupons is sidebar-only and there is no creator-side Store/Shopify surface at all.
  • Frontend mock-mode caveat — the SPA renders mock data unless VITE_API_MODE=live. The 403/200 probes prove the backend is live; confirm the deployed frontend build actually ships VITE_API_MODE=live or every page silently shows canned data over a real API.
