A DB-level unique index was deliberately deferred pending a prod duplicate-row check (see new finding EV-179 in FINAL_PRODUCTION_AUDIT.md §11). Built and tested in an isolated fix checkout — not committed, not this RC.

## 7. Notable "green tests, red reality" pattern (why the pass counts overstate readiness)

This RC repeatedly shows the pattern this team has previously flagged as a systemic risk ("Mock stubs the layer the bug lives in" — project memory): a service-layer test suite is green because it runs against H2/mocks, while the real MySQL schema or real external gateway behaves differently.

- `AffiliateSettlementJobTest` PASS, but real MySQL rejects the ENUM value the job writes (EV-011).
- `WalletServiceTest` PASS, but the real `VARCHAR(64)` column overflows on real withdrawal idempotency keys (EV-014).
- 3621/3621 Java unit tests green, but the application **cannot boot** at all (EV-001) — none of those 3621 tests load a full Spring context.
- `BrandDeliverableServiceTest` 32/32 PASS, but the tested "approve" flow does not actually release money in production because `milestoneId` is never populated (EV-019) — the unit tests never assert the cross-service linkage.
