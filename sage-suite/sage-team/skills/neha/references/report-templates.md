# Report Templates & Rules

This file defines the exact Markdown template, the health-percentage math, and the verdict rules used by both `scripts/build_report.py` and any hand-written fallback report. Read this when you need the precise format or when the script can't run.

## Health percentage

The report shows a single "health %" so anyone can see at a glance how close the code is to shippable. It is a weighted score, not a raw pass/fail count, because one Critical bug matters far more than five cosmetic ones.

```
start at 100
subtract per finding:
  Critical → 25
  High     → 10
  Medium   → 4
  Low      → 1
floor at 0, round to nearest whole number
```

A run with zero findings = 100% ✅. This mirrors the model-scheduler-audit "completion %" idea so the two dashboards feel consistent.

## Overall verdict rules

Compute the verdict from the highest-severity finding present:

- Any **Critical** → `FAIL` (block ship).
- Any **High** (no Critical): `FAIL` if any finding is Security or Build type; otherwise `PASS WITH REQUIRED FIXES`.
- Only **Medium/Low** → `PASS`.
- No findings → `PASS ✅`.

## Markdown template (also the hand-written fallback)

```markdown
# 🧪 Test Report: <task>

- **Date:** <YYYY-MM-DD>
- **Target:** <paths / feature / URL>
- **Stages run:** <Build, Functional, Security, AI>
- **Health:** <NN>%
- **Verdict:** <PASS ✅ | PASS WITH REQUIRED FIXES ⚠️ | FAIL ❌>

## Summary
| Severity | Count |
|----------|-------|
| Critical | <n> |
| High     | <n> |
| Medium   | <n> |
| Low      | <n> |

## Findings by tester

### <Tester> — <Type>  (verdict: PASS/FAIL)
#### [<SEVERITY>] <title>
- **Where:** <file:line / endpoint>
- **Issue:** <what's wrong and why it matters>
- **Fix:** <concrete remediation>

(repeat per finding; group Critical first, then High, Medium, Low)

## Next steps
- Route <Critical/High> blockers to <Ananya frontend / Vikram backend> via Arjun.
- Escalate Critical to Swapnil via Kavya/Priya.
- Re-run the same stage after fixes before final PASS.

_Generated by the `tester` skill. Native per-tester reports live in wiki/errors, wiki/security, wiki/ai-review, wiki/processes._
```

## HTML dashboard

The script emits a self-contained HTML file (inline CSS, no external assets) with:
- a header showing task, target, date, big health % ring, and the verdict badge;
- a severity summary row (Critical/High/Medium/Low counts as colored tiles);
- one collapsible section per tester, findings sorted Critical→Low, each color-coded by severity.

Severity colors (keep consistent with dataviz conventions): Critical `#c0392b`, High `#e67e22`, Medium `#f1c40f`, Low `#3498db`, Pass/OK `#27ae60`.
