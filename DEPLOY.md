## 1. What's in this project

Influora is **three services in three languages**, plus supporting infrastructure. All of it lives in this one repo.

| Service | Folder | Language / Stack | Build | Runtime port |
|---|---|---|---|---|
| **Web SPA** (frontend) | `src/` (root project) | TypeScript — Vite 6 + React 19, react-router-dom v7 | `npm ci && npm run build` → static `dist/` | 80 (nginx) |
| **Core API** | `influora-api/` | Java 21 — Spring Boot 3.3.5 (Maven) | `mvn clean package` → JAR | 8080 |
| **AI service** | `influora-ai/` | Python 3.13 — FastAPI (Uvicorn) | `pip install -r requirements.txt` | 8000 |

Supporting data services (via Docker): **MySQL 8**, **ClamAV** (malware scan), **Redis**.

**Where the actual code is:** `src/` (frontend), `influora-ai/app/` (Python), `influora-api/src/` (Java).

## 2. What is NOT in this zip (on purpose)

To keep it small and safe, this archive **excludes**:

- `node_modules/`, `influora-ai/.venv/`, `influora-api/target/` — regenerated by the build commands below.
- `dist/`, `test-results/`, `playwright-report/`, `screenshots/` — build/test output.
- `.git/`, `_archive/`, `_to_delete/` — history and scratch.
- **Real secret files: `.env.local`, `influora-ai/.env`, and `scratch_jwks_repro/`** — never share these. Use the `*.env.example` files as templates and generate fresh secrets per `BLUEPRINT/06`.

The `.env.example` templates ARE included so you know the shape of the config.

## 3. Run locally (development)

```bash
# --- Data services (MySQL + ClamAV) ---
docker compose up -d

# --- Frontend (from repo root) ---
npm ci
npm run dev            # Vite dev server

# --- Core API (Java 21 + Maven required) ---
cd influora-api
# create influora-api/.env from .env.example, then:
mvn spring-boot:run

# --- AI service (Python 3.13) ---
cd influora-ai
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
# create influora-ai/.env from .env.example, then:
uvicorn app.main:app --reload --port 8000
```

Copy each `*.env.example` to its real `.env` and fill in values before starting. See `BLUEPRINT/06` for exactly which key goes where.

## 4. Deploy to production (summary)

Full walkthrough: **`BLUEPRINT/10-RUN-ON-SERVER-UTHO.md`**. The short version:

1. **One server, Docker only.** Each service has its own multi-stage `Dockerfile` — you do NOT install Node/Java/Python on the host. Recommended box: **4 vCPU / 8 GB RAM / 80 GB SSD** minimum (ClamAV + Playwright Chromium are memory-hungry).
2. **Generate all secrets** on the server (script in `BLUEPRINT/06 §3`). Every signing secret must be distinct and ≥32 bytes. Put them in `*.env` files with `chmod 600` — **never in Git**.
3. **Three DNS hostnames** point at the box: `app.` (frontend), `api.` (Core API), `ai.` (AI SSE stream). The frontend talks to the API directly, so all three need TLS.
4. **TLS first** (nginx + Certbot) — login uses a `Secure` cookie that won't work over plain HTTP.
5. **Build & start** with a `docker-compose.prod.yml` (template in `BLUEPRINT/10 §6`). Order: MySQL/Redis/ClamAV → API (Flyway runs 56 migrations) → AI → frontend.
6. **Verify** each health endpoint and confirm the frontend bundle baked in YOUR `api.` URL.

### The one trap that costs everyone hours
Vite bakes every `VITE_*` value into the JS bundle at **build time**, not run time. Changing a `VITE_*` value requires **rebuilding the frontend image** — `docker compose restart` re-serves the old bundle. (Java and Python read config at run time, so `env_file:` works for them.)

### Before go-live
Back up `INFLUORA_PII_EMAILPHONEENCRYPTIONKEY` and `INFLUORA_PII_BANKENCRYPTIONKEY` **off the server**. Lose them and every encrypted email/phone/bank row is permanently unreadable — a DB backup alone won't save you.

## 5. Handy commands

| Task | Command |
|---|---|
| Frontend build | `npm run build` |
| Frontend lint | `npm run lint` |
| API build | `cd influora-api && mvn clean package` |
| AI deps | `cd influora-ai && pip install -r requirements.txt` |
| Prod status | `docker compose -f docker-compose.prod.yml ps` |
| Prod logs (one service) | `docker compose -f docker-compose.prod.yml logs -f influora-api` |
| Kill AI spend | set `AI_SPEND_KILL_SWITCH=true` in `ai.env` → restart `influora-ai` |
